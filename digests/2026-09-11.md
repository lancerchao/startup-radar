## Ideas

Three candidates deep-dived this cycle, all rejected — the thirty-eighth straight cycle with zero survivors, and all three land in the same meta-category (AI-coding-agent ecosystem tooling), now confirmed the single most over-mined shape on this ledger.

### 1. PAT-to-GitHub-App credential migration tool for small teams (post mandatory-2FA enforcement) — REJECTED (new)

- **Brief description:** A guided migration tool that converts a small team's bot/service-account personal access tokens (PATs) used in CI/CD to short-lived GitHub App tokens, after GitHub's September 2, 2026 mandatory 2FA enforcement started auto-removing non-2FA bot accounts from organizations and breaking their pipelines.
- **Risks:** The complete fix is GitHub's own free, first-party feature, and the internet is already full of free walkthroughs for exactly this migration.
- **Buyer pain (quantified):** Real but bounded — bot/service accounts without 2FA are auto-removed from orgs, silently breaking CI/CD authentication; one documented real-world migration example touched 30+ repositories and 6 custom GitHub Actions, but that scale is enterprise-tier, not solo/small-team.
- **Why now, not 2 years ago:** Dated and real — enforcement fully landed September 2, 2026, nine days before this digest.
- **Why don't existing big players compete — they don't need to, they already shipped the fix:** GitHub Apps are GitHub's own recommended, native, free replacement for bot-account PATs — short-lived (1hr) tokens, scoped permissions, no license seat consumed, purpose-built for exactly this migration.
- **Why isn't it saturated yet — because there's nothing to sell:** At least five independent free technical walkthroughs (dev.to, bmterra.eu, systemshardening.com, brtkwr.com, convoluted.io) already cover the PAT-to-App migration step by step; GitHub's own Expert Services and existing DevOps consultancies already serve the harder, larger-scale end of this market (reported migration-service pricing $1,000–$50,000+ depending on repo count/complexity) — the segment left in between (a solo dev or small team with a handful of repos) is a few hours of free-guide-following work, not a product.
- **What will change in the next 2 years:** Nothing structural — this is a one-time migration per team, already absorbed once GitHub's own docs and free community guides are followed.
- **Competitors:** GitHub Apps (native, free), GitHub Expert Services / DevOps consultancies (paid, enterprise-scale), 5+ free public migration guides.
- **Who pays / sales motion:** Would be self-serve developer tooling, but there's no paid gap between "free 30-minute guide" and "$1K+ professional migration service" for a small team's actual repo count.
- **Expected CAC / LTV / ARR ceiling:** Near zero — a one-time task with a free fix doesn't generate recurring revenue, and the audience most affected (small teams, few repos) is exactly the segment for whom the free guides are already sufficient.
- **Time to first sellable version / Operational load:** Could ship a wizard/CLI in days, which only underscores why it isn't worth building — the underlying steps are already documented free by GitHub itself.
- **Sources:** [Hacker News thread on mandatory 2FA](https://news.ycombinator.com/item?id=48976781), [dev.to — GitHub Apps vs PATs](https://dev.to/patelaryan66/why-github-apps-are-better-than-personal-access-tokens-for-automation-1lg9), [systemshardening.com — SCM identity choice](https://www.systemshardening.com/articles/cicd/scm-identity-choice/), [brtkwr.com — migrating a bot user to a GitHub App](https://brtkwr.com/posts/2026-01-06-migrating-from-github-bot-user-to-github-app/).
- **Kill reason:** GitHub's own free, native GitHub Apps feature is the complete fix, already documented by at least five independent free guides; the pain is one-time and bounded to a few hours for the small-team buyer this idea would target, leaving no recurring-revenue product between "free guide" and the existing paid enterprise migration-services market.
- **Not scored against B2C_RULES** — B2B/developer tooling, buyer is a small-team operator, not a personal consumer.

### 2. AI Agent Skills supply-chain security scanner for small teams/enterprises — REJECTED (new)

- **Brief description:** A pre-install security scanner for "Skills" (the SKILL.md format Anthropic open-sourced in December 2025, now adopted by OpenAI's Codex/ChatGPT and Gemini CLI) that checks third-party skills for prompt injection, data exfiltration, and other malicious patterns before a developer or team installs them from a community directory.
- **Risks:** The exact detection mechanism this idea would sell is already free, open-source, and shipped by a hardware giant with more distribution than a solo founder could match.
- **Buyer pain (quantified):** Real and severe — Snyk's February 2026 ToxicSkills audit found 1,467 malicious payloads across 3,984 scanned skills (36% flaw rate), 76 confirmed carrying active malicious payloads, distributed via the ClawHub directory; a separate coordinated campaign that same month used 30+ malicious skills against Claude Code/OpenClaw users; the broader MCP ecosystem (10,000+ servers as of April 2026) has ~38% of servers from unofficial sources, ~3% with hardcoded credential-theft traps (Clutch Security, Dec 2025).
- **Why now, not 2 years ago:** Genuinely fresh — the Skills spec itself is under a year old (Dec 2025), and the malicious-skill campaigns and audit data are from this year.
- **Why don't existing big players compete — they already did, and one of them is Nvidia:** Nvidia open-sourced SkillSpector (Apache 2.0), which detects 71 vulnerability patterns across 17 categories — prompt injection, data exfiltration, privilege escalation, supply chain, excessive agency — across Claude Code, Codex, and MCP skills, pre-install; it already has 16,900 GitHub stars. Sentry separately ships a free skill-scanner with the same detection scope. Snyk (the auditor that surfaced the problem) already ships free agent-scan/mcp-scan tooling too.
- **Why isn't it saturated yet — it is, at the free tier that matters most:** Three independent, credible, free tools (one from a $4T hardware company) already cover this exact function before a paid entrant could ship.
- **What will change in the next 2 years:** SkillSpector and Sentry's scanner both keep iterating detection patterns as new attack techniques surface — the same fast-moving free-incumbent dynamic that has killed every AI-agent-tooling idea on this ledger so far.
- **Competitors:** NVIDIA SkillSpector (free, OSS, 16.9k stars), Sentry skill-scanner (free), Snyk agent-scan/mcp-scan (free) — plus this ledger's own 2026-08-11 rejection of the closely-related CLAUDE.md/.cursorrules poisoning scanner idea (Snyk + ClawGuard, same pattern).
- **Who pays / sales motion:** Would be self-serve developer/security tooling, but the free tier is backed by a hardware giant with a security research team and no revenue pressure to monetize the scanner itself.
- **Expected CAC / LTV / ARR ceiling:** Near zero — competing against a free tool from Nvidia is not a fundable position for a solo founder.
- **Time to first sellable version / Operational load:** An MVP wrapping static pattern matching could ship in 1-2 weeks, but SkillSpector already ships the more sophisticated two-stage (static + LLM semantic) version, free, today.
- **Sources:** [Snyk — ToxicSkills study](https://snyk.io/blog/toxicskills-malicious-ai-agent-skills-clawhub/), [NVIDIA SkillSpector (GitHub)](https://github.com/nvidia/skillspector), [Sentry skill-scanner](https://mcpservers.org/agent-skills/sentry/skills/skill-scanner), [Stacklok — Enterprise IT Security Guide to Claude + MCP](https://stacklok.com/blog/the-enterprise-it-security-guide-to-claude-and-mcp/), [Protego — Claude Code Skills and MCP Security Risks 2026](https://protego.me/blog/claude-code-skills-mcp-security-risks-2026).
- **Kill reason:** Nvidia already open-sourced a 16,900-star, free, more technically sophisticated version of this exact scanner (SkillSpector), with Sentry and Snyk both shipping free equivalents — the third confirmation on this ledger that AI-agent-tooling security ideas die to a free incumbent, this time a hardware giant rather than a startup.
- **Not scored against B2C_RULES** — B2B/developer tooling, buyer is a small-team operator or enterprise security team, not a personal consumer.

### 3. Cross-agent Skills sync/version-control tool for teams ("one canonical skill, many agents") — REJECTED (new)

- **Brief description:** A tool that lets a team maintain one canonical SKILL.md and automatically propagate it, kept in sync, across every AI coding agent surface they use — Claude Code, Cursor, Codex, Copilot, Gemini CLI — preventing drift as the same skill gets manually copy-pasted and diverges across tools.
- **Risks:** A free, open-source, actively-maintained tool with real adoption already does exactly this.
- **Buyer pain (quantified):** Real but thinly evidenced beyond adoption momentum — the Agent Skills spec (open-sourced by Anthropic December 2025) has been adopted across OpenAI's Codex CLI/ChatGPT, Gemini CLI, and Cursor within roughly nine months, meaning any team using more than one coding agent now faces a genuine multi-surface consistency problem; no independent survey/complaint-volume data found quantifying how many teams are actually affected.
- **Why now, not 2 years ago:** Real — the format and its multi-vendor adoption are both under a year old, so the "drift across tools" problem didn't structurally exist before 2026.
- **Why don't existing big players compete — they don't need to, an open-source project already solved it:** skills-manager (MIT license) is a cross-platform (macOS/Windows/Linux) desktop app explicitly built to "manage, sync, and organize AI agent skills across 50+ coding tools," with 4,700 GitHub stars, 396 forks, and 569 commits of active development.
- **Why isn't it saturated yet — it is, across both halves of the mechanic:** skills-manager covers the sync/organize half; a separate tool, skill-editor, covers the canonical-source/drift-prevention half ("edit canonical SKILL.md files and replicate updates to Claude, Codex, and Cursor"); Skills Board and mdskills.ai additionally cover install/registry workflows — every layer of the pitch already has a free, live tool.
- **What will change in the next 2 years:** More agents adopt the spec, which only strengthens skills-manager's free cross-tool value proposition rather than opening room for a paid alternative.
- **Competitors:** skills-manager (free, OSS, 4.7k stars), skill-editor (free), Skills Board, mdskills.ai.
- **Who pays / sales motion:** Would be self-serve developer tooling, competing directly against a free tool with an 18-month-plus head start on stars/forks/commit velocity relative to a new entrant.
- **Expected CAC / LTV / ARR ceiling:** Low — developers are the buyer segment most likely to just use the free, open-source option already in front of them, especially when it already supports 50+ tools.
- **Time to first sellable version / Operational load:** An MVP could ship in 1-2 weeks, but it would ship behind a free tool with 4.7k stars and active weekly development.
- **Sources:** [skills-manager (GitHub)](https://github.com/xingkongliang/skills-manager), [skill-editor (skills.rest)](https://skills.rest/skill/skill-editor), [duet.so — Claude Code Skills Complete Guide](https://duet.so/guides/claude-code-skills-complete-guide), [Skills Board — manage skills across Claude/Codex/Cursor](https://www.skillsboard.sh/guides/manage-skills-across-claude-codex-cursor).
- **Kill reason:** skills-manager already ships the exact free, open-source, actively-maintained cross-agent sync tool this idea describes, with 4.7k stars and real commit velocity, and adjacent free tools (skill-editor, Skills Board) already cover the canonical-source and registry angles this idea would need to differentiate on.
- **Not scored against B2C_RULES** — B2B/developer tooling, buyer is a small-team operator or solo developer, not a personal consumer.

**Bottom line:** Thirty-eighth straight cycle, zero survivors. All three candidates this cycle clustered in the same meta-category — AI-coding-agent ecosystem tooling — because it was genuinely the freshest, most dated signal source this week (GitHub's Sept 2 2FA enforcement, Snyk's Feb 2026 ToxicSkills audit, and the Skills spec's rapid multi-vendor adoption are all real, current events). All three died the same way this ledger keeps finding in this specific meta-category: a free, open-source tool from either the platform itself (GitHub Apps) or a well-resourced incumbent (Nvidia's 16.9k-star SkillSpector, the free skills-manager project) already ships the exact mechanic before a solo founder could differentiate.
